# Unframe LP Design Guide

## 目的

この文書は、`lp/` の現行実装から読み取れる視覚言語、レイアウト、コンポーネント、コンテンツ表現を整理したデザインガイドです。新しいページやセクションを追加するときは、実装の詳細だけでなく、ここに記載する意図と原則を基準にします。

- 対象: `lp/src/` のランディングページ、News、Docs、エラーページ
- 技術構成と運用手順: `lp/README.md`
- プロダクト全体の構成: `ARCHITECTURE.md`
- 実装上のデザイントークン: `lp/src/app.css`

この文書は現行コードの静的な確認に基づきます。ブラウザ、実機、スクリーンリーダーによる表示・操作確認は別途必要です。

## ブランドコンセプト

中心となるメッセージは **Present beyond the frame.** です。従来の長方形のスライドから、奥行き、方向、視点、移動を含む空間へプレゼンテーションを広げます。

視覚表現では、次の概念を一貫して扱います。

| 概念               | 視覚表現                                       |
| ------------------ | ---------------------------------------------- |
| フレームからの解放 | ビューポートを横断する波形、画面端まで続く余白 |
| 空間と奥行き       | 非対称グリッド、重なり、異なる縮尺の文字       |
| 視点と移動         | 軌道、矢印、方向性のある小さなモーション       |
| 流動性             | Blue、Purple、Red が連続するグラデーション     |
| 思考のための静けさ | 暖かい明色背景、細い罫線、抑制した色面         |

デザインはプロダクト UI を模倣するのではなく、Unframe の思想を伝える編集的な紙面として構成します。抽象的なメッセージだけに寄りすぎず、プロダクトの具体的な価値や実態も同じページ内で示します。

## デザイン原則

### 空間を余白で表す

要素をカードで埋め尽くさず、大きなセクション余白と疎な配置によって空間性を表現します。余白は装飾ではなく、情報の階層と移動のリズムを作る要素です。

### 大きな言葉と小さな説明を対比する

英語の Display Heading で思想や方向性を短く提示し、日本語本文で意味を補います。巨大見出しを長文説明の代わりにはしません。

### ブランドカラーを面で使いすぎない

Blue、Purple、Red は、文字、番号、アイコン、細線、波形に限定して使います。大面積の背景は基本的にニュートラルカラーとし、グラデーションの希少性を保ちます。

### 動きは方向を示すために使う

モーションは注意を奪う演出ではなく、奥行きや移動方向を補助するために使います。移動量は小さく、常時アニメーションは低速にします。

### 実態と表現を一致させる

CTA は必ず有効なリンク先または処理を持たせます。未実装機能、構想、開発中の機能を現在利用できる機能として表現しません。デモ、ラベル、代替テキストは実際の内容と一致させます。

## ページ構成

### Home

ホームはプレゼンテーションのように番号を持つセクションで構成します。

| 順序 | セクション   | 番号 | 役割                                 |
| ---- | ------------ | ---- | ------------------------------------ |
| 1    | Hero         | 00   | ブランドメッセージと主要導線         |
| 2    | News         | なし | 最新情報の挿入枠                     |
| 3    | Concept      | 01   | プロダクトが扱う問題と思想           |
| 4    | Features     | 02   | 空間的なプレゼンテーションの構成要素 |
| 5    | Product Demo | 03   | 体験を具体化するメディア             |
| 6    | Use Cases    | 04   | 利用場面と対象者                     |
| 7    | Vision       | 05   | 長期的な方向性と開発への導線         |

News は本編の章番号を進めない更新情報として扱います。セクションを追加するときは番号の意味とページ全体の物語を更新します。

### News / Docs

News と Docs は `ContentIndex.svelte` と `ContentArticle.svelte` を共有します。マーケティングページと同じ見出し、罫線、色、余白を使いながら、読みやすさを優先して幅を絞ります。

- 一覧: 最大幅 `1100px`
- 記事: 最大幅 `820px`
- 一覧カード: 2列からモバイルの1列へ切り替え
- 記事タイトル: Display Heading を使用
- 本文: 広めの行間と明確な見出し階層を使用

### Error Page

エラーページも通常ページと同じブランド体系に含めます。巨大見出し、グラデーション、丸形アクションを使い、復帰先を明確にします。

## レイアウト

### コンテナ

| 用途                                     | 最大幅   |
| ---------------------------------------- | -------- |
| マーケティングセクション、Header、Footer | `1440px` |
| News / Docs 一覧、Error                  | `1100px` |
| News / Docs 記事                         | `820px`  |

主要コンテナの水平ガターは次を基準にします。

| ビューポート | ガター |
| ------------ | ------ |
| 640px 未満   | `24px` |
| 640px 以上   | `40px` |
| 1024px 以上  | `56px` |

### グリッド

デスクトップでは、均等な2列よりも情報の役割に応じた非対称グリッドを優先します。

- Concept: `1.05fr / 0.95fr`
- Features: `0.55fr / 1.45fr`
- Vision: `0.7fr / 1.3fr`

モバイルでは読み順を保った1列にします。視覚的な配置のために DOM の意味的な順序を崩しません。

### 垂直リズム

主要セクションの標準的な上下余白は、モバイルで `128px`、640px 以上で `176px` です。

- News は更新情報として `48px` から `64px` に抑える
- Features は Concept との連続性を保つため上余白を持たない
- Vision は Footer へ連続させるため下余白を抑える
- 見出しから本文・導線までは、おおむね `28px` から `48px`
- 見出し群からカードや罫線までは、おおむね `96px` から `112px`

## カラー

実装上の基準色は `lp/src/app.css` の `@theme` に定義します。

| トークン       | 値        | 用途                           |
| -------------- | --------- | ------------------------------ |
| `background`   | `#f7f7f5` | ページの基本背景               |
| `foreground`   | `#15171d` | 基本文字色                     |
| `night`        | `#0b0e14` | 見出し、ボタン、濃い文字       |
| `night-soft`   | `#11151d` | Night の補助色                 |
| `muted`        | `#747780` | 説明文、補助情報               |
| `line`         | `#dedfe2` | 罫線、区切り                   |
| `brand-blue`   | `#7187f5` | グラデーション始点、空間表現   |
| `brand-purple` | `#9a80d0` | グラデーション中点、フォーカス |
| `brand-red`    | `#df7b80` | グラデーション終点、アクセント |

現行実装で `#ececf0` を使うセクション背景は、基本背景と区別する **Surface** として扱います。新規実装ではハードコードせず、トークン化して共通利用することを推奨します。

ブランドグラデーションは `Blue -> Purple 48% -> Red` の順序を維持します。グラデーション文字は大きな見出しや短い番号に限定し、本文やリンクの意味を色だけで伝えません。

通常サイズの文字は WCAG AA の `4.5:1`、大きな文字と UI の境界は `3:1` を最低基準にします。透明度付きの `night` やブランドカラーは、実際の背景と合成したコントラストを確認します。

## タイポグラフィ

### フォントファミリー

```css
--font-sans: "Inter", "Noto Sans JP", "Helvetica Neue", Arial, sans-serif;
--font-display: "Inter", "Helvetica Neue", Arial, sans-serif;
```

現行実装は Inter と Noto Sans JP を配信していないため、表示は利用環境に依存します。意図した組版を保証する場合は、ライセンスと配信コストを確認したうえでフォントを明示的に配信します。

### Display Heading

- Weight: `300`
- Letter spacing: `-0.055em`
- Line height: `0.97`
- Size: セクションに応じた `clamp()`
- 用途: ページの `h1`、主要セクションの `h2`

Hero は `clamp(4.1rem, 10.8vw, 10.5rem)`、通常セクションはおおむね `clamp(3.2rem, 7vw, 7rem)` を基準にします。負の字間は英語の大見出しを前提とし、日本語タイトルでは文字の衝突と可読性を個別に確認します。

### Eyebrow / Section Label

- Size: `0.68rem`
- Weight: `600`
- Letter spacing: `0.19em`
- Line height: `1.2`
- 表現: セクション番号、32px の細線、短いラベル

小さな日本語に広い字間を適用するため、可読性とコントラストを必ず確認します。

### 本文

- マーケティング本文: `14px` から `18px`
- 行間: `24px` から `32px`
- 記事本文: `1.05rem`、line-height `2`
- 1行の幅: 説明文はおおむね `320px` から `512px` に制限

英語の見出しは概念、日本語の本文は意味と利用価値を説明します。日英で同じ内容を重複させるのではなく、相互に補完させます。

## ブランド要素

### GradientWave

`GradientWave.svelte` は、15本の細いベジェ曲線で空間の流れを表す主要モチーフです。

- 装飾として扱い `aria-hidden="true"` を維持する
- セクションごとに固有の SVG gradient ID を指定する
- 本文の可読性を妨げない透明度で使う
- 向きの反転はセクション間の流れを作る場合に限る
- ロゴの代わりには使わない

### Logo / AnimatedIcon

Header は動きを持つ SVG アイコン、Footer は静的なロゴを使います。アニメーションは初回のブランド提示に限定し、装飾の場合はアクセシビリティツリーから除外します。

ロゴアセットは `assets/` と `lp/static/brand/` に分散しているため、追加や更新時は両方の利用箇所を確認します。OGP 画像と画面上のブランド表現も一致させます。

### Icon

基本アイコンは Lucide の細いストロークを使用します。

- 標準 stroke width: `1.1` から `1.8`
- アイコンだけで意味を伝える操作には accessible name を付ける
- 装飾アイコンは本文の読み上げを重複させない
- 異なるアイコンセットの混在は、ブランドアイコンなど必要な場合に限定する

## コンポーネント

### Header

- ページ上端に絶対配置し、Hero またはページヘッダーへ溶け込ませる
- 最大幅とガターはマーケティングコンテナに合わせる
- 768px 以上は横並びナビゲーション、未満はメニューボタン
- すべてのページで明色背景上の視認性を保つ
- 現在地を `aria-current` で示す

モバイルメニューは Escape、外側クリック、フォーカス移動、トリガーへのフォーカス復帰を含むキーボード操作を提供します。

### Footer

- Surface 背景上にロゴ、説明、主要リンク、著作権を配置する
- 背面の波形は低い透明度にする
- 長い日本語を `nowrap` に固定せず、320px 幅でも欠けないようにする
- 外部リンクと連絡先を明確に区別する

### SectionLabel

番号、細線、短いラベルを一体として使います。番号はホームの物語上の順序を表し、装飾目的だけで追加しません。

### Button

ボタンは丸形、適度な水平余白、小さな方向モーションを基本とします。

| Variant   | 用途                                 |
| --------- | ------------------------------------ |
| `primary` | ページ内の主要アクション             |
| `accent`  | ブランド色を必要とする強いアクション |
| `outline` | 背景と同化させる副次アクション       |
| `quiet`   | 低い優先度のテキストアクション       |

遷移先がある操作はリンク、状態を変更する操作はボタンとして実装します。処理のないボタンやリンク風の非インタラクティブ要素は作りません。

### Content Index / Article

News と Docs の表示構造は共有し、コンテンツ種別による差は文言、アイコン、日付、戻り先に限定します。記事本文で使う `h2`、`h3`、リンク、リスト、引用、コード、画像、表には個別のスタイルを用意します。

## インタラクションとモーション

標準の easing は `cubic-bezier(0.22, 1, 0.36, 1)` です。

- ボタン: hover で最大 `2px` 上へ移動
- 矢印: 意味する方向へわずかに移動
- アイコン: 回転または水平・垂直方向へ最大 `4px` 程度移動
- 一覧カード: hover で最大 `4px` 上へ移動
- Hero の軌道: `24s` の低速な連続回転
- Header アイコン: 初回表示時に上下から reveal

hover で示す状態は `focus-visible` または `focus-within` でも認識できるようにします。`prefers-reduced-motion: reduce` では smooth scroll、常時アニメーション、意味のない transition を停止します。

## レスポンシブ

Tailwind の標準ブレークポイントを使います。

| Breakpoint | 幅          | 主な変化                                  |
| ---------- | ----------- | ----------------------------------------- |
| Base       | 320px 以上  | 1列、24px ガター、モバイルナビゲーション  |
| `sm`       | 640px 以上  | 40px ガター、文字・余白の拡大、一部複数列 |
| `md`       | 768px 以上  | Desktop navigation、カードの2から3列化    |
| `lg`       | 1024px 以上 | 56px ガター、非対称グリッド、装飾軌道     |

見出しは `clamp()` で連続的に拡縮します。`overflow-x: hidden` によって問題を隠さず、320px、375px、768px、1024px、1440px でテキスト、ロゴ、カード、動画のはみ出しを確認します。

## アクセシビリティ

- ページごとに一意な `h1` を持たせ、`h2`、`h3` の順序を飛ばさない
- `header`、`nav`、`main`、`section`、`article`、`footer` を役割に合わせて使う
- 共通 Header の前後に本文へ移動する skip link を提供する
- キーボード利用時にすべての操作要素へ明確な focus indicator を表示する
- 通常文字 `4.5:1`、大きな文字と UI `3:1` のコントラストを保つ
- `forced-colors` でもグラデーション文字が消えない代替色を用意する
- タッチターゲットは原則 `44px` 四方以上にする
- 装飾 SVG は読み上げ対象から除外し、意味のある画像・動画には内容に一致する代替情報を付ける
- 自動再生、速い点滅、大きな視差効果は使用しない

## コンテンツ

### 言語

- Display Heading: 短い英語で方向性を伝える
- Section Label: 短い日本語で章の役割を伝える
- 本文: 日本語で具体的な意味、利用価値、前提を伝える
- CTA: 遷移後に起きることが分かる日本語を使う

英語は雰囲気だけの語句にせず、日本語本文と合わせて一つの意味を作ります。

### News / Docs Frontmatter

```mdx
---
title: "ページのタイトル"
description: "一覧に表示する説明"
order: 1
publishedAt: "2026-07-18"
---
```

`publishedAt` は News の日付表示に使います。ホームの News は公開日順、一覧は registry の `order` 順であるため、コンテンツ追加時は意図した順序を両方で確認します。

### CTA とリンク

- CTA の文言と遷移先を対応させる
- ページ内アンカーは対象の `id` が存在することを確認する
- 外部リンクは Organization、Repository、Issue など行き先を意図して選ぶ
- リンク先が未定の場合は CTA 自体を表示しない
- 開発中または構想段階の内容は、その状態が分かる文言を添える

## 禁止事項

- 有効な処理やリンク先を持たない CTA
- 存在しない ID を指すページ内リンク
- 実際のプロダクトと無関係なデモを正式なデモとして表示すること
- 未実装機能を現在利用可能な機能として記載すること
- トークン外の色を理由なく追加すること
- 小さな文字へ低コントラスト色を使うこと
- hover のみに依存して意味や状態を伝えること
- 意味的な見出し順序を見た目の都合で崩すこと
- 狭い画面で文章を欠けさせる `white-space: nowrap`
- ブランドグラデーションを大面積へ多用すること

## 現行実装の課題

以下はデザインガイドの推奨事項ではなく、確認時点の実装との差分です。

1. Header の「試してみる」は `href` も処理も持たないボタンです。
2. Use Cases のリンク先 `#contact` は、CTA セクションが非表示のため存在しません。
3. Product Demo はプロダクトと無関係なプレースホルダー動画です。
4. `night/30` から `night/50` など、小さい文字でコントラストが不足する箇所があります。
5. Inter と Noto Sans JP は指定されていますが、サイトから配信されていません。
6. Features はセクションの `h2` がなく、見出し階層が `h3` から始まります。
7. モバイルメニューに Escape、フォーカス移動、フォーカス復帰などの操作がありません。
8. Footer の説明文は `whitespace-nowrap` により狭い画面で欠ける可能性があります。
9. Surface 色 `#ececf0` が複数箇所にハードコードされています。
10. 記事本文は `h3`、リンク、コード、引用、画像、表のスタイルが未定義です。
11. 通常リンクの focus 表現と、カードの `focus-within` 表現が統一されていません。
12. Header と Footer でロゴの形式とアセットの参照元が異なります。

## QA チェックリスト

新しいページやセクションを追加したら、次を確認します。

- [ ] 320px、375px、768px、1024px、1440px で横方向にはみ出さない
- [ ] 英語と日本語の見出しが不自然に衝突・改行しない
- [ ] ページに一意な `h1` があり、見出し順序が連続している
- [ ] Tab、Shift+Tab、Enter、Space、Escape で操作できる
- [ ] すべてのリンク、CTA、ページ内アンカーが有効である
- [ ] hover と focus の両方で状態を認識できる
- [ ] 通常文字と UI が所定のコントラストを満たす
- [ ] `prefers-reduced-motion` で不要な動きが停止する
- [ ] forced colors または high contrast でも文字と操作要素が見える
- [ ] 画像、SVG、iframe の代替情報が実際の内容と一致する
- [ ] 長い日本語タイトル、0件、1件、多数件のコンテンツで崩れない
- [ ] OGP のタイトル、説明、画像がページ内容と一致する
- [ ] `pnpm --filter @unframe/site run check` が成功する
- [ ] `pnpm --filter @unframe/site run test` が成功する
- [ ] `pnpm --filter @unframe/site run build` が成功する
