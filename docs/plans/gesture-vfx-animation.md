# Gesture VFX Animation 実装計画

作成日: 2026-11-04。状態: Draft 実装中。認識と必須演出の独立モジュールを追加済み。実通信への接続と実機受入は未実施。現在の API は各モジュールの README を参照する。

[演出案 spec-visual.md](https://github.com/unframe-dev/unframe/blob/main/docs/plans/spec-visual.md) を基準に、Unity のジェスチャー認識と Unity／Web 両方の演出を制作する。認識結果の取り出しと演出の起動を独立した API にし、チームメイトが既存のプレゼンテーション規格と Realtime に接続できる状態で引き渡す。

## 確定した要件

- ジェスチャー認識は Unity が担当する。Web 側での手やコントローラーの認識は追加しない。
- 「投げる」は横から振りかぶり、一定速度以上で目線の前方へ腕を振る動作とする。上投げは除外する。
- 「円を描く」は片手の時系列の軌跡から認識する。
- 「粒子になって消える」は、まずノイズで表面を徐々に消すディゾルブとして制作する。実際の粒子分解は初期実装に含めない。
- すべての VFX はサイズ・色・速度を変更可能にする。認識閾値もコードを書き換えずに調整可能にする。
- 単発演出は一度起動したら一回再生して終了する。手元の発光・残光は操作中に継続し、操作終了後に残光を消す。

## 時間制約を踏まえた実行方針

接続用 API は制作側で決定し、動作する呼び出し例とともに引き渡す。統合担当との事前合意を着手条件にしない。今回の完成条件は、認識結果を取得でき、Unity／Web それぞれで API から演出を起動・終了できることとする。実通信への組み込みと復旧の受入は統合担当の後続作業とする。

初期版はコントローラーのトリガーで認識を開始し、円は正面の平面、不透明な静的モデルをディゾルブの受入対象とする。調整は Unity Inspector と簡素な Web プレビューで行い、専用の調整画面や軌跡の記録ツールは後回しにする。追加候補の演出は必須分が完成して余力がある場合だけ制作する。

接続用に残すものは、認識結果のコールバック、単発演出の起動、外部時刻による更新、キャンセル・完了通知、手元演出の開始・Pose 更新・終了とする。通信の再送管理や終了済み ID の履歴保存は統合側に任せる。

## 現在の実装との境界

Unity の [PresenterRecognition](../../app/unity/Assets/Scripts/PresentationRuntime/Quest/PresenterRecognition.cs) は既存の8種の認識を持つが、投げる・円は持たない。[QuestPresentationInput](../../app/unity/Assets/Scripts/PresentationRuntime/Quest/QuestPresentationInput.cs) は認識と既存通信の接続点になる。認識ロジックは通信や Cue 実行に直接依存させない。

Web の Audience は 8th Wall と Three.js を使う。演出は既存 Scene に追加し、別の XR セッションや描画ループを立ち上げない。WebGL は描画、WebXR は XR デバイスへのアクセスを扱う別の役割である。Three.js の現行 WebGLRenderer は WebGL 2 を使用するため、Web 演出は既存の Three.js／WebGL 描画内に実装する。[Three.js 公式資料](https://threejs.org/docs/pages/WebGLRenderer.html)、[WebXR 仕様](https://immersive-web.github.io/webxr/)。

既存 Timeline の対象は opacity／position／rotation／scale であり、ディゾルブの進行度や新しい VFX Run をそのまま表現できる前提にはしない。正式契約の拡張は統合担当と協議する。[Presenter authority 契約](../packages/CONTRACT_PRESENTER_AUTHORITY.md) と [Runtime 契約](../packages/CONTRACT_RUNTIME.md) を維持し、独自通知で共有状態を変更しない。

## ジェスチャー認識

### 入力と状態

時刻付きの手位置、頭位置・向き、追跡有効性、操作開始・終了を入力にする。初期版の開始・終了操作は既存のトリガー操作を踏襲する。素手での開始・終了操作が必要な場合は別途確定する。

認識状態を `idle → capturing → recognized または canceled → idle` とし、開始時の入力文脈と頭向きの水平成分を保持する。途中の頭の回転で判定軸を変えない。追跡喪失、不正な時刻、大きなサンプル欠損、入力世代変更、再校正で途中認識を破棄し、復帰直後の位置差を動作として扱わない。

一回の捕捉につき確定通知は最大一回とする。呼び出し側が認識開始時に投げる／円を明示選択する。既存ジェスチャーとの競合調停・入力文脈の保持は統合側が担当する。

### 投げる

1. 捕捉開始時の頭向きから水平前方・左右・上方の基底を作る。水平前方が安定して取れない場合は認識を開始しない。
2. 頭位置を基準にした手の軌跡から、横側・後方への振りかぶりを検出する。
3. 続く前方スイングについて、前方速度・前方移動距離・前方との角度・所要時間を検査する。速度は実サンプルの時間差で計算し、平滑化して一フレームの跳びを除く。
4. 上下成分の割合と軌跡を検査し、上投げや縦振りを除外する。条件成立時に一回だけ通知する。

速度だけでは前押しや腕の戻しを誤認するため、振りかぶりから前方スイングへの順序を必須にする。実際の物体の把持・解放は認識条件に含めない。

| 調整項目                               | 単位と意味                             |
| -------------------------------------- | -------------------------------------- |
| 振りかぶり最小距離                     | m。横側・後方への準備動作の下限        |
| 前方最低速度                           | m/s。前方成分の速度下限                |
| 前方最小距離                           | m。小さな震えを除く下限                |
| 前方許容角度                           | 度。水平前方からのずれの上限           |
| 上下成分の上限                         | 比率。縦方向の動きを除外               |
| 判定時間窓・平滑化時間・再認識待ち時間 | ms。速さの違い・ノイズ・重複反応の調整 |

### 円を描く

初期案は、捕捉開始時の目線に対して正面の平面へ手の軌跡を投影し、円形を判定する。時計回り・反時計回りとも受け付ける。任意方向の三次元の円への対応は、必要性を確認してから判断する。

等距離に再サンプリングした軌跡へ円を当てはめ、半径範囲、半径誤差、始点と終点の近さ、中心周りの累積角度、回転方向の一貫性、奥行きのずれを検査する。始点と終点が近いだけでは、往復動作や折れ線も成立するため不十分である。一周が成立した時点で確定し、操作し続けても連続発火させない。

調整可能にする値は、最小・最大半径（m）、閉じ判定距離／半径の比率、半径誤差率、必要回転角（度）、逆方向移動の許容割合、奥行き誤差（m）、最小サンプル数、最短・最長判定時間（ms）とする。

### 調整と観測

Unity の設定アセットと Inspector から値を変更できるようにする。専用の実行時調整 UI は後続対応とする。調整中の設定は捕捉開始時に固定し、変更値は次回の捕捉から適用する。初期値は仮値として実機で決める。

軌跡・判定速度・円の推定半径と誤差・不成立理由を確認できるデバッグ表示を用意する。通常利用時は無効にする。テスト用サンプルを認識器へ再入力して判定を再現する。実機の軌跡記録ツールは後続対応とする。

## 演出の制作範囲

元仕様の優先候補・追加候補を維持し、まず必須分を完成させる。追加候補は時間に余裕がある場合だけ着手する。

| 演出               | 優先度   | 実装方針と終了条件                                                                                 |
| ------------------ | -------- | -------------------------------------------------------------------------------------------------- |
| 左右からのウェーブ | 必須     | 左右の長い波線を時間差で背後へ回り込ませる。背後で交差し、両端の移動を続けながら減衰して一回で終了 |
| 手元の発光・残光   | 必須     | 操作中に発光と短い軌跡を表示。終了・キャンセル・追跡喪失時に放出を止め、残光を消す                 |
| ノイズによる消失   | 必須     | 対象表面の表示領域をノイズ閾値で徐々に減らし、一回で完全に消す                                     |
| スワイプの光の弧   | 追加候補 | 入力方向へ短い弧を流して消す                                                                       |
| 確定時の波紋       | 追加候補 | リングを広げ、減衰して消す                                                                         |
| モデルを包む光の帯 | 追加候補 | 対象の境界サイズを基に帯を一周させ、尾を消す                                                       |

ウェーブの外観は [GradientWave.svelte](../../app/web/lp/src/lib/components/brand/GradientWave.svelte) を参照する。LP の画面用実装をそのまま MR 空間へ移植せず、波形・配色・時間差を参照する。

全 VFX に `size`（基準寸法への正の倍率）、`color`（sRGB の RGBA、各成分 0〜1）、`speed`（正の再生速度倍率）を用意する。基準尺 `durationMs` に対し実再生時間を `durationMs / speed` と定義し、移動・発生・減衰の時間を同じ倍率で進める。色とサイズの意味は両環境で揃える。演出固有の線幅・波数・ノイズ密度等は別設定にし、共通項目へ混ぜない。

### ノイズ消失の方針

Unity は既存 URP と整合するシェーダー、Web は Three.js のマテリアル／シェーダー拡張で作る。ノイズ値と進行度を比較して表面を切り抜き、必要に応じて消失境界だけを発光させる。初期版は追加の大量粒子や全画面 Bloom を前提にしない。

ノイズの座標系・模様の寸法・seed を揃える。静止したノイズ模様に対して閾値を進め、開始時は元の表示、終了時は完全消失を保証する。透明素材、複数マテリアル、SkinnedMesh、影、輪郭について対象素材を決めて確認する。粒子より軽量になるかは対象端末で測定し、切り抜きだけで性能を保証しない。

初期受入は不透明な静的モデルで行う。PNG／動画面、透明・半透明モデル、SkinnedMesh は対象素材を確認して受入範囲を確定する。共有マテリアルを直接変更せず、他の表示物を巻き込まない。終了後の恒久的な Node 非表示や削除は統合側が確定し、演出モジュールは素材や Node を勝手に削除しない。

## 外部からの起動とデータ受け渡し

### 起動 API 案

以下はエンジン内で使う意味上の API 案であり、新しい通信形式の確定ではない。Unity と TypeScript で同じ意味の型を定義し、正式な共有契約へ昇格させる場合は `packages/contracts/` を正本とする。

```ts
const handle = effects.play({
  runId: "preview-1",
  effectId: "wave",
  placement: { kind: "stage" },
  size: 1,
  color: [0.4, 0.3, 1, 1],
  speed: 1,
  durationMs: 1200,
  seed: 42,
  startedAtRuntimeMs: 10000,
});

effects.evaluate(10600); // Runtime 時刻を渡して途中位置を表示する
handle.cancel();
```

呼び出し側は「何を・どこで・いつから・どの設定で再生するか」を渡す。`placement` は Stage、対象 Node、手元を区別する型にし、必要な参照がない入力を拒否する。座標・回転・寸法は既存 Presentation Space 契約に従い、Unity／Web の座標変換は各アダプターが担当する。

起動 API に加え、手元の発光用の `begin / updatePose / end`、明示キャンセル、完了通知、進行位置の復元を提供する。具体的な型名・配置先・引数は制作側で固定し、呼び出し例とともに公開する。

### 認識結果

認識器は `throw / circle`、使用した手、開始・成立時刻、診断用の速度・円の誤差等を通知する。捕捉開始時の入力文脈は通信アダプターまで維持する。VFX 用の発生位置・方向は認識種別と分け、共有空間への変換が必要な値を明示する。

診断値や手軌跡を既存 GestureInputCommand に無断で追加しない。Gesture 種別の追加には Proto だけでなく、Definition、各言語の入力検証、認識 catalog、生成物とテストの更新が必要になる。手追従の連続演出に必要な Pose は既存の経路への接続を統合担当と決める。

### 再生の約束

- 実行中の `runId` が同じ起動の再適用で演出を増殖させない。同じ ID の異なる内容は拒否する。終了済み ID の再送排除は統合側が担い、演出側は履歴を保持しない。
- 単発演出の進行は `clamp((runtimeNowMs - startedAtRuntimeMs) * speed / durationMs, 0, 1)` で評価する。受信時刻やフレーム数を開始基準にしない。
- pause 中は Runtime 時刻を止めれば表示も止まる。同じ seed・進行位置に対して各環境で対応する外観を出す。ピクセル単位の一致は要求しない。
- 終了済みの演出を遅れて受信しても最初から再生しない。途中参加時に復元するか省略するかは統合担当が決め、復元する場合は指定時刻から描けるようにする。
- 終了・キャンセル時に演出専用リソースを解放する。対象の最終表示状態と進行は Runtime が所有し、描画側の完了通知で Cue を直接進めない。
- 手元の残光を途中位置から復元するには過去の Pose が必要になる。初期案では新しい有効 Pose から残光を作り、過去の軌跡を捏造しない。pause 中の保持方法は統合テストで確認する。
- 不正な数値、未知の演出、存在しない対象、同時実行上限超過には明示エラーを返す。設定の初期値・上下限は一覧で公開する。

## テストと受入

認識ロジックと時間評価は描画から分離し、失敗テストを先に追加してから実装する。シェーダーの見た目や端末性能は自動テストのみでは確認できないため、実機受入を別途行う。

| 対象     | 確認項目                                                                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 投げる   | 左右の手、正常な振りかぶりと前方投擲、閾値直前・直後、遅い腕振り、上投げ、前押し、腕の戻し、頭の回転、移動中、追跡復帰時の跳び |
| 円       | 時計回り・反時計回り、大きさと速さの境界、半円、楕円、直線往復、8の字、閉じない円、奥行きのずれ、ノイズ、異なるサンプル頻度    |
| 通知     | 同一捕捉の一回通知、既存8種との競合と早期確定の防止、キャンセル、Step／入力世代変更時の破棄、設定変更の次回適用                |
| 起動 API | 数値境界、対象参照、重複 ID、同時起動、速度と寿命、途中位置、完了済み入力、キャンセルとリソース解放                            |
| 表示     | 全演出のサイズ・色・速度、ディゾルブの完全消失、複数素材への影響、繰り返し再生時の状態復元                                     |
| 統合     | Unity と Web の同じ Run、遅延・重複受信、pause／resume、Step 終了、再接続・途中参加時の合意済み挙動                            |

認識品質は意図した動作の成功率と、通常操作・既存 Gesture の誤検出率を分けて記録する。使用できる実機で正例・負例を確認し、試行回数・成功数・誤検出数・反応遅延を記録して引き渡す。

性能は対象 Quest と対象スマートフォン／ブラウザで、演出なしとの差分 CPU／GPU フレーム時間、描画回数、同時再生数、メモリ、繰り返し後の残存リソースを測定する。目標 FPS と許容追加時間を先に決め、満たさなければ波線数・ノイズ計算・画面占有率等を調整して再測定する。

実装時は Unity EditMode と必要な PlayMode／実機確認、`nix run .#audience`、`nix run .#check` を実施する。正式契約を変更した場合は生成・drift 検証を追加する。Unity と Audience の通信を接続した受入には、利用可能な licensed Unity Editor で `nix run .#realtime-e2e -- --unity --race` と手動の演出確認を行う。

## 引き渡し時に明記する事項

- 初期版は正面の円とコントローラー操作に対応すること。
- 完成した演出の一覧と呼び出し例。Gesture と演出の割り当ては統合側で変更できること。
- ディゾルブの対象素材と、消失完了・キャンセル・Step 復元時の対象表示状態。
- 対象 Quest、スマートフォン、ブラウザと、認識精度・遅延・描画性能の合格値。
- 制作側で決定した起動 API の型と手元 Pose の入力方法。途中参加・再接続・配送への接続は統合側の担当であること。
