# Audience Webアプリ開発への移行

- 更新日: 2026-10-22
- 状態: 位置保持PoCはユーザー承認により完了。Webアプリの製品機能はこれから実装する。
- 所有アプリ: `app/audience/`。編集用の`app/web/`と分離する。
- 統合先: `webXR/audience`。今回の`webXR/tracking-poc`はPoCの記録・実装・開発基盤を段階別にコミットする。統合と次の作業ブランチ作成は別の作業として扱う。

## 引き継ぐ構成

[採用記録](../experiments/audience-apriltag-adopted.md)と[Audience README](../../app/audience/README.md)を追跡の基準とする。

- AprilTag `tag36h11`の単一ID 0。姿勢が一度有効に取れたら即確定する。
- 次の観測まで8th Wall absolute SDK／SLAMで位置を保持する。未検出・曖昧姿勢では前のアンカーを維持する。
- SDK追跡低下・hidden・停止では非表示にし、新しいタグ認識を要求する。
- 確定値から表示を分離し、距離別の上限付き閾値内の小揺れだけを抑える。閾値を超える変化は即反映する。
- カメラ権限、NORMAL待機、Worker、GPU読取、姿勢推定、描画、停止・復帰の所有と破棄の境界を保つ。
- JSON診断と入力画像の明示保存を開発時の調査に利用する。製品UIでの公開方法はアプリ開発時に決め、自動アップロードしない。

現構成はユーザーが開発開始に十分と評価した基準であり、7m認識・外部真値に対する10cm誤差・不可視5〜10分保持を定量実証したものではない。追跡方式の再選定や追加実験を開発開始の条件にはしない。

## 製品方針

Unframeは無償。会場の観客はログイン・登録なしでサイトを開き、ルームIDを入力して参加する。会場内で登壇者と同じ空間・進行を視聴する。現PoCのカメラ画面だけでルーム参加・プレゼン再生が実装済みとは扱わない。

## 実装順序

| 順序 | 実装範囲                            | 完了条件                                                                                       |
| ---- | ----------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1    | 観客向けの画面と状態の設計          | ルーム入力、参加処理、権限取得、位置合わせ、視聴、追跡低下、終了とエラー復帰の遷移を定義する   |
| 2    | 位置合わせと視聴画面への追跡統合    | PoCの検出・確定・SDK保持・表示補正を再利用し、開始・終了・再入場でリソースが重複しない         |
| 3    | 既存公開成果物の表示                | 実際のmanifestとPNG等の契約を再確認し、座標・寸法・透過・ページ切替と非対応表現を扱う          |
| 4    | ログイン不要の参加契約とBackend接続 | 現行identity必須joinとの違いを解決し、匿名viewerの資格・ルームID解決・参加可否・期限を検証する |
| 5    | ライブ同期と途中参加・復帰          | ブラウザで利用できるtransportと状態契約を実装し、進行追従・切断復帰・退出・資格失効を検証する  |

Backend共有契約が必要な作業では、先に既存実装と契約境界を確認して定義する。既存gRPC bidiがブラウザからそのまま利用できるとは仮定しない。素材URLの期限更新、CORS、キャッシュ、メモリ予算も実装と合わせて定義する。未実装の経路を動作するAPIとしてUIへ接続しない。

各変更は機能単位でコミットし、PoCで確認した追跡の動作を製品機能の変更と混在させない。製品機能の追加・不具合修正は通常のTDDと対象領域の品質ゲートに従う。PoC時の軽いデバッグ指定は実験の履歴として残す。
