# ジェスチャーの接続と引き継ぎ

Throw／Circle は既存8種類と同じ Source trigger・認識カタログ・GestureInputCommand を使用する。正式な契約・送信・サーバー経路は main に統合済みで、この変更は認識品質と制作側の出力境界を整える。

## 認識条件

- Throw: 開始時の水平な目線を前方として固定。後方12cm・後方との3D角度35度以内で振りかぶり、前方20cm以上・平均前方速度1.2m/s以上・直近0.12秒の3D方向35度以内で成立。往路と復路の一致は不要。
- Circle: 目線に正対する縦平面で円・楕円を認識。初期値は長軸/短軸約2:1まで。閉じ・回転角320度・逆行・奥行き8cmなどの条件を併用し、実際の軌跡を結果に保持。

詳細とAPIは [認識README](../app/unity/Assets/Scripts/VisualEffects/Gestures/README.md) を参照。

## 担当境界

制作側は認識と周期位置通知までを提供する。`QuestPresentationEntry` は通知を同じ Update 内で集約し、既存 TrackingFrame の送信を促す。通常の0.1秒間隔と同じ送信枠を使い、送信中や流量制限中の通知を蓄積しない。座標と時刻は送信時に既存経路で取得する。受信側は既存の Anchor 投影と HandGlow 描画を使う。

手動診断シーン・ログ出力・専用ビルドメニュー・Unity/Web の独立デモ画面は削除した。製品の Local Editor の正式なシミュレーション操作と、自動回帰テストは維持する。

## 検証

ユーザーによる実機確認で投げ・円の認識成立を確認済み。統合時に Unity 6000.3.27f2 の対象 EditMode テストと、Realtime／Audience の追跡・Anchor・描画に関する対象テストを実行済み。詳細は統合PRの検証記録を参照する。周期通知を接続した通信経路の Quest／スマートフォン実機受入は未実施。
