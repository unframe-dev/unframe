# 大判タグ：初回7m認識と単フレーム自己位置の計測

> 履歴（2026-10-22）：現在の実装は[AprilTag採用方式](./audience-apriltag-adopted.md)のみ。以下は当時の方式・スキーマ・実証の記録であり、削除済みの比較モードやコマンドを現行仕様として使用しない。

更新日: 2026-10-20。状態: 計測基盤を実装。実機結果は未取得。要求精度の達成報告ではない。

## 目的と範囲

[再設計](../plans/audience-tracking-redesign.md)のG0〜G2の準備として、設置外寸50/60/70cmで初回7mの検出・自己位置を比較する。現在のソルバーは既存の独自POSIT探索であり、公式AprilTag／IPPE参照ソルバーとの比較は未完了。ブラウザのカメラ・描画は引き続き8th Wallを使うため、SDK再選定も未完了である。

検出と姿勢推定は静止した一枚から実行する。このモードではSLAMを無効にする。不可視5〜10分の保持は評価できず、別の移動追跡・統合試験で扱う。

## 寸法と起動

| 設置外寸（白い余白込み） | 黒い検出境界 | URLのsize |
| ------------------------ | ------------ | --------- |
| 50cm                     | 約33.33cm    | 50        |
| 60cm                     | 40cm         | 60        |
| 70cm（既定）             | 約46.67cm    | 70        |

1. `/print-target.html?mode=tag&detector=april&size=70`で同条件のタグを用意する。ArUcoはdetector=arucoにする。
2. 外寸と黒い検出境界の幅・高さを実測する。出力の丸め表示ではなく、設定は外寸の正確な2/3を使う。支持面の平面性と余白を保つ。A4への縮小印刷や、画面上のCSS寸法を実寸保証として扱わない。
3. HTTPSの`/?mode=tag&detector=april&size=70`を開く。印刷ページとカメラ画面のsize・detectorが一致していることを確認する。設定変更は停止中に行う。
4. タグとカメラを固定し、カメラ光学中心からタグ中心までの斜距離を測る。光学中心を厳密に定められずレンズ位置で近似する場合は、その計測不確かさを試験記録に残す。
5. 測った斜距離を「実測距離」に入力し、カメラを開始する。未測定なら空欄にする。開始後は値を固定する。移動・距離変更後は停止し、測り直して再開する。
6. 同じ撮影画像に表示される軸、最小辺画素数、推定斜距離、実測との差を確認し、ログを保存する。

距離差はタグ中心への斜距離の誤差で、奥行きZの誤差でも、会場内3D位置誤差でもない。向きが誤っていても距離だけ合う場合があるため、これだけで約10cmの表示精度に合格させない。会場自己位置・向きの精度には設置位置とカメラ姿勢の外部計測が必要である。

## 試験条件

端末・OS・ブラウザ版、カメラ解像度、検出器版、size、実寸、紙／画面、照明、反射、距離、角度、固定方法を記録する。まず固定・明るい条件から始め、その後に斜視・ブレ・暗い会場条件を追加する。

- 検出試験: 1/3/5/7m、外寸50/60/70cm、正面と斜視を比較する。
- 姿勢試験: 近距離で較正・座標・ソルバーを切り分けた後、大判タグの3/5/7mへ進む。近距離ではタグ全体が収まる距離を使う。
- 初回7m試験: アプリ起動時から7mに置き、近づいて一度読ませる操作をしない。初検出と有効な自己位置の取得を別に記録する。
- 外れ値試験: タグを隠す、映像が停止する、画面を切り替える条件で、古い姿勢が現在値として残らないことを確認する。

成功率の反復回数、初回待ち時間、角度・位置の誤差予算は事前に決める。現UIは成功率や3D精度の自動合否を表示しない。位置が未推定でも角の画素数は検出の証拠として記録できる。

## ログの読み方

tag／anchorの現行schemaVersionは7。旧tagのschemaVersion 6とは追加情報の有無を区別する。`tag.frame`は同一入力の角・K・両検出器処理時間・sourceVideoTime・自己位置・画素数・斜距離比較を含む。sourceCallbackAtMsとcallbackAgeAtResultMsはSDKコールバック基準であり、露光・表示までの正確な遅延ではない。

`measurementSnapshot`はadapter生存期間の累積値。停止・再開しても数え続けるためsessionIdとsession.startの条件を区別する。入力した実測距離は各tag.frameにも保存する。

- capture.updates: SDK callback数。センサー固有フレーム数ではない。
- capture.captured/error/skipped: 取得成功・エラー・最初に該当した除外理由。busyやinterval等の重複する理由を二重加算しない。
- capture.lastFrameMetadata: 最後の取得の寸法・K・投影・クロップ・時刻の出自。露光時刻・歪み・補正状態・地図epochは未確認として明示する。
- detection: `submitted = delivered + stale + cancelled + error + pending`。completedはWorker正常終了数でキャンセル後の後着結果も含み、この和に追加しない。deliveredは両検出器の比較結果をアプリへ渡した数で、タグ検出成功数ではない。
- droppedSamples/droppedTransitions: 容量上限で明細が欠けた数。ログの明細だけで全セッションの検出成功率・精度分布を算出しない。特に5〜10分試験には別の保持評価基盤が必要。

観測の有効期限はSDK取得コールバックから500ms。受信時に検査し、100ms周期の監視でも期限切れの自己位置とプレビューを消去する。これは精度保証や実露光からの上限ではなく、入力停止を古い成功表示で隠さないための条件である。

画像の保存・アップロード機能は追加していない。検出器そのものの再評価に必要な画像データセットは、開発者が明示的に収集する別の試験として準備する。

実機の解像度・クロップを確認する手順と追加ログ項目は[高解像度入力の調査・R0計測](./audience-high-resolution-investigation.md)を参照する。
