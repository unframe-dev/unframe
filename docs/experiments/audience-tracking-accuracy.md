### 移動時の姿勢探索・原点ライフサイクルの修正（2026-10-20）

ユーザーから「最初は実物と合い、端末移動中にずれ、少しの揺れでも原点を失う」と報告された。実用精度には達していない問題として再監査した。

**探索不足の再現。** ログ5のframe152／376では、各マーカーのPOSIT二解から作った全候補が同じ悪い局所解へ収束していた。追加の初期値なしでは再投影RMS約1.946／2.868px、直前から約39／51度跳んだ。直前姿勢を探索初期値に追加すると同じ8角でRMS約0.662／0.865pxの解を得られた。ambiguity=falseはこのケースで正解の一意性を保証していなかった。独立した合成投影とノイズのfixtureでもRMS4.271→0.552pxとなる探索不足を再現し、TDDで修正した。ユーザーの角座標はテストへ転載していない。

`estimateBoardPose`は追加初期値を明示的に受け取り、全候補を同じ再投影目的で最適化する。Appは直前500ms以内の有効姿勢をSDKの相対回転と、既知ならメートル尺度付き並進で伝播する。前値への強制平滑化・成功閾値の緩和ではない。SDK追跡喪失・停止・再スキャンで探索値を破棄する。再スキャン前のWorker結果が後から探索値を復活させる競合も、処理冒頭のtimestamp判定と回帰テストで修正した。

**観測棄却と原点失効の分離。** 単発の悪いボード観測で変換を削除していた処理を修正した。低品質観測は補正へ使わず変換を保持する。否定観測が500ms続けば描画を止めて再確認し、既存閾値内の良観測3回で自動復帰する。未検出だけではこの再確認を開始せず、再確認済みなら未検出で解除しない。既存の20cm／0.35radを超える大差は、500ms以内の3候補が相互に既存の3cm／0.08rad以内で整合した場合のみ失効させる。SDK追跡喪失と明示リセットによる原点破棄は維持した。

**効果と限界を分ける。** 同じ新ライフサイクルでseedなし／ありを比較すると、ログ5の全PnP再投影RMSの95%点は1.362→0.986px、SDK相対運動を除いた回転変化95%点は8.05→5.49度となった。一方、locked中の推定位置差95%点は17.73→17.26cm、最大53.28cmで、全体のずれは解消していない。原点削除をやめたこと自体を精度向上と扱わない。

最終ライフサイクルを含む再生は全414フレーム中、描画可能92、再確認で非表示109、較正中213、失効0。再確認4回から良観測による自動復帰2回、残りは再スキャンまたはログ終了となった。seedの有無でこの状態件数は同じで、状態件数から姿勢推定の精度改善を主張しない。数秒連続の大残差区間を描画継続で隠さず非表示にしていることを確認した。オフラインで既存の角情報を再生した結果であり、実機改善の実証ではない。

## 目的と現在の結論

初回検出距離・時間を改善し、画像から離れた後も共有原点と表示を維持する。検出と位置保持は別に測定する。「NORMAL」「較正成功」だけを実空間精度の証拠としない。完全な無誤差は未実証であり、実測で評価する。

既存ログの最後の較正から約13秒間、画像更新13件、画像ロスト0件、記録されたフレームはNORMALだった。それでも固定原点に対する後続の画像推定は、初期換算で最大約54.3cm相当、回転最大約45度、スケールは初期の約41〜98%に変化した。これはSDK観測間の差であり、物理的な測定結果ではない。画像ロストだけでは説明できず、カメラ姿勢を欠いた旧ログでは画像推定とSLAMの寄与を分離できない。

## 実装した比較条件

画面開始前のフォームで条件を選び「条件を適用」するとページを再読み込みする。queryは列挙値のみ許可する。起動中にSDKの追跡方式を変更しない。`target=venue`が従来画像、`target=detail`が新しい比較画像。選んだ認識データと印刷・画面表示リンクを一致させる。

| profile         | SDK設定                                              | 描画・目的                                                                                                       |
| --------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| baseline (A)    | absolute / World Trackingあり / 実寸メタデータなし   | 従来のSDK設定を対照にする。較正平均化・残差監視は他のworld条件と共通。旧実装そのものを再現する条件ではない。     |
| responsive (B)  | responsive / World Trackingあり / 実寸メタデータなし | Aとの差は尺度設定のみ。画像の実幅でscene unit/mを求める。                                                        |
| fixed-width (C) | B＋physicalWidthInMeters=設定幅 / moveable=false     | 公開ソースに基づく実寸・固定画像指定の仮説検証。使用SDKが反映することは未確認。                                  |
| image-only (D)  | responsive / World Trackingなし / 実寸メタデータなし | 画像観測に毎回追従し、ロスト時に消す。画像検出と画像に対する描画の対照。原点保持・画像外の追跡を成功扱いしない。 |

A/B/Cは初期の安定期間の位置・回転・スケールを逐次平均して原点を確定する。安定性の比較基準は最初の観測を保持し、徐々に動く推定へ追随して誤採用しない。ロック後は原点と画像の位置・角度・スケール差を監視する。2cm相当・0.03rad・3%のいずれかを超える観測が1秒継続し、観測間隔500ms以下ならdriftedとして表示を停止する。一発の異常値では失効させない。再スキャンまたはresetでやり直す。

これは誤表示を維持しない措置であり、SLAMの誤差を補正した結果ではない。画像が見えない期間は残差を測れない。画像の再観測へ常時追従するDも、実空間の原点保持の解決策ではない。

## 実施したオフライン実験

### 画像の局所コントラスト比較

既存依存のsharp、自作SVG、公式CLIで別のdetail-boardを生成した。外部写真・新規依存は使わず、既存画像は置き換えていない。原画900×1200、実寸想定30×40cm、CLI生成輝度画像480×640。各4×4領域へ大小の非反復形状を分散させた。

| 幅480での指標                     | 従来venue | 比較detail |
| --------------------------------- | --------: | ---------: |
| 5×5近傍の輝度差16未満の平坦画素率 |    82.88% |     35.41% |
| 局所勾配40以上の画素率            |     7.19% |     32.81% |
| 4×4領域で最も低い上記勾配率       |     3.28% |     24.91% |

幅240・120でも比較した。指標の定義と全結果はスクリプトがJSONへ出力する。これは局所コントラストの代理指標であり、SDKの特徴点数・認識率・認識距離ではない。細かすぎる模様や画面のモアレで悪化する可能性もあり、実機比較が必要。

### 既存実機ログの再解析

`analyze-tracking-log.mjs`で固定anchorと、その後の画像推定との位置・角度・スケール差を再計算した。最後の区間は位置差0.2938 scene units、初期換算0.5433m相当、最大角度差45.00度、スケール比0.4122〜0.9790を再現した。旧ログは画像更新が約1秒に間引かれており、500msの連続性判定を含む較正処理を忠実にリプレイしたものではない。

### 初期較正の平均化

固定seed、500試行、各21観測・50ms間隔で、既知の真値へ独立・平均ゼロの位置／回転／スケールノイズを加えた。位置RMSは最初の1観測の5.960mmから平均値の1.336mmへ低下した。試行は単体テストとして再実行できる。

これは相関のあるSDK誤差、カメラ・画像・SLAMの系統誤差、距離変化時のドリフトを再現していない。実機が1.336mm精度になったという意味ではない。

## ログ変更

schemaVersion 3。実験条件・実際にSDKへ渡した設定・エンジン版・映像寸法を保存する。画像観測は最大5Hz、カメラのみのフレーム要約は最大1Hz、較正残差は新しい画像から生成されたときだけ最大5Hzで保存する。

公開SDKはCPU処理で画像イベントを通知してからonUpdateを呼ぶため、画像を次のonUpdateまで保留し、その処理結果のカメラ姿勢と組み合わせる。画像受信時刻とカメラ採取時刻も別々に保存する。画像を見失った後に古い残差を新しい観測として再記録しない。

高頻度サンプル最大2000件と状態遷移最大1000件を別に保持し、起動証拠がフレームログだけで追い出されないようにする。上限を超えた件数はdroppedSamples/droppedTransitionsに記録する。SDKオブジェクトは取得時に複製する。精度判定にはログの欠落も確認する。

## 旧方式で計画した実機実験（未実施・現行手順ではない）

この環境からユーザーのiPhoneのカメラ・移動・照明を操作できないため、以下は用意した比較条件での共同測定となる。ブラウザの画面確認・単体テストを実機での精度改善の実証とはしない。

1. PCで選択と一致する画像を幅30cmで表示。画像の縦横比は3:4を維持。端末・照明・画面倍率・画面輝度を固定し、床や机に0.5m・1m・2mの印を付ける。
2. 最初にD＋従来画像、D＋比較画像を比較。近づく前に各距離から開始し、10秒以内の初回検出成否と所要時間を3回ずつ測る。近くで認識してから遠ざかった結果を初回認識距離と混同しない。
3. 同じ画像でAとBを比較し、その後BとCを比較する。毎回停止・再読み込みして別の起動として記録する。SDKがCを無視する可能性を残す。
4. 0.5mで較正後、画像を映したまま1m・2mへゆっくり移動。実物の中心・辺とワイヤーのずれ、初期の30cm軸と物差しの寸法一致、drifted発生を記録する。
5. 同じ条件で画像を視野外へ5秒出し、元の位置へ戻す。再観測残差と実物とのずれを分けて評価する。
6. 最良候補について、同じ画像のマット印刷を同寸法で比較し、画面の反射・モアレ・表示解像度の影響を調べる。

暫定の測定目標は、まず1mからの初回検出と、0.5→1m移動で実物位置から5cm以内の表示保持を再現できることとする。製品としての最遠席・許容誤差の合意値ではなく、現状の約50cm認識から改善を判断するための目安。未達の場合は新画像を成功扱いせず、画角・画素占有率・カメラの推定移動・画像姿勢・スケール比をログで比較する。会場の最遠席では画像ボードの大型化や複数配置も別途検討する。
