# タグ位置の単発更新とSDK保持

> 履歴（2026-10-22）：現在の実装は[AprilTag採用方式](./audience-apriltag-adopted.md)のみ。以下は当時の方式・スキーマ・実証の記録であり、削除済みの比較モードやコマンドを現行仕様として使用しない。

2026-10-21。タグ姿勢が得られるごとに会場対応を即座に更新し、次の更新まではSDK／SLAMで移動をつなぐ。

## 動作

- 既存のNORMAL連続5秒後の検出開始、選択検出器のみ、最大頻度、画像解像度維持を使用する。
- 黒外周15cmの単一ID 0が既定。有効なタグ姿勢と撮影callback時点の有効なSDK姿勢を1ペア得れば、即反映する。残差ゲート・複数回の一致待ち・平滑化は行わない。
- 復号だけ成功して姿勢が曖昧、再投影誤差超過、SDK姿勢欠落なら新位置は作らず、前の有効位置を保持する。姿勢のない検出結果から位置を捏造しない。500ms以上古い結果は既存のadapterと採用側で除外する。
- 未検出中もSDK内の物体行列を固定し、SDKカメラの位置・回転で描画する。タグ更新時の計算は検出完了時の最新SDK姿勢へ置換しない。SDKの通常描画ループで表示するため、検出Hzや診断画像の最大5Hzはライブ描画頻度を制限しない。
- LIMITED・hidden・停止で表示を隠し、対応を破棄する。NORMAL復帰だけで古い位置を再表示せず、新しいタグ姿勢を要求する。追跡低下前の遅延結果は採用しない。

## 座標

Tをタグ推定venueFromCamera、Sを同じ取得callbackのsdkFromCameraとすると、`sdkFromVenue = S * inverse(T)`。箱・軸の行列を`sdkFromVenue * venueFromMarker`へ即更新する。次のタグ観測までこの行列は変更せず、SDKカメラが動く。独自の移動距離尺度較正やSDK回転への置換はない。タグ姿勢が揺れればライブ表示も即座に跳ねるため、この試験ではその挙動も記録する。

## 表示と記録

背景の箱・軸がライブ表示。下の緑・ピンクの比較は同一撮影画像の診断であり別表示。タグ採用回数と最終タグ取得からの経過時間を表示する。

ログはschema17 / mode anchor-comparison、ファイル名audience-anchor-comparison-log.jsonを維持する。`experiment.presentation`はlive-tag-update-with-sdk-hold。frameごとに`anchorUpdated`と`anchor`（採用通算回数・最後のタグ取得callback時刻・sdkFromVenue行列）を保存し、top-levelにも最新状態を保存する。`anchor.cleared`は追跡低下・hidden・停止による破棄理由を記録する。比較計算・候補診断・処理時間・実効Hzは継続記録する。停止すると現在アンカーはnullになるが、recordsに採用履歴は残る。
