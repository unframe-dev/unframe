# AprilTag即時更新＋SDK保持の採用とコード整理

2026-10-22。ユーザーの実機評価を受け、観客向けPoCをAprilTag `tag36h11`・単一ID 0と8th Wall SDK／SLAMの方式に一本化した。現行仕様はこの文書と[Audience README](../../app/audience/README.md)。過去の実験文書とJSONは検討・測定の履歴として残し、旧コードへの互換経路は用意しない。

## PoC完了と採用判断（2026-10-22）

距離別の小揺れ補正を含む現在の構成について、ユーザーが「十分な精度を達成した」と判断し、PoCの終了とWebアプリ開発への移行を承認した。AprilTag単一ID 0、有効姿勢の即時確定、次の検出までのSDK／SLAM保持、追跡低下時の非表示と再認識、表示専用の上限付きブレ補正を採用構成として引き継ぐ。

実機認識距離の報告は黒外周150mmで約3.3m、240mmで約5.8m。旧目標の7m・誤差10cm・タグ不可視5〜10分保持を外部真値で定量実証したこととは区別する。これらの追加実証をWebアプリ開発開始の条件にはしない。追跡方式の比較・再選定は終了し、以降の変更は製品上の必要性に基づき扱う。

[Webアプリ開発計画](../plans/audience-web-app-plan.md)を次の作業の入口とする。ルーム参加・プレゼン表示・ライブ同期は未実装。

## 採用動作

1. 有効なタグ姿勢と同じ取得callbackのSDK姿勢を1ペア得たら即更新する。確定値には一致待ち・平滑化・複数回の合意・残差ゲートはない。表示専用の小揺れ補正は末尾の仕様に従う。
2. 次の有効な更新まではSDK座標内のアンカー行列を固定し、SDKカメラの移動と回転で表示を保持する。
3. 未検出・姿勢が曖昧な間は前の位置を保持する。復号だけで姿勢がない場合、再投影誤差超過、SDK姿勢欠落、500ms以上の古い観測も新しい位置として採用しない。
4. SDK追跡低下、hidden、停止では表示を隠して対応を破棄する。NORMALへ戻っただけで再表示せず、新しい有効タグを要求する。

SDKはabsolute固定。NORMAL連続5秒後に検出器を生成し、同時1フレーム・最大速度で処理する。準備中の追跡低下では待ち直す。最初の認識で観客を移動させる独自尺度較正は行わない。検出中にLIMITEDになっても検出器は動かし、SDK姿勢を持たない結果は位置更新に使わない。

`SDK姿勢 × inverse(タグ由来会場姿勢) × マーカー配置`を確定値として即更新し、表示層で小揺れだけを抑える。タグが得られない間は表示行列を維持する。

## 採用判断の範囲

ユーザーから約3.2m付近まで、立ち位置を変えなければ良好に保持できたという報告があり、プレゼン視聴中は観客の立ち位置を固定する前提で進める。外部真値による10cm誤差、5〜10分保持、7m初回認識の達成を確認したものではない。移動中の精度・長時間保持は未実証。ArUcoよりAprilTagが良いという実機所感は現在の実装・環境での選定根拠とし、方式一般の優劣としない。

## 表示の小揺れ補正・初期固定閾値（2026-10-22、距離別設定へ更新済み）

ユーザー報告では黒外周150mmで約3.3m、240mmで約5.8mを認識し精度は良好だが震えがある。距離は実機所感であり外部真値による精度検証ではない。

確定処理とSDKカメラは変更せず、SDK座標内のマーカー表示だけをタグ採用時に補正する。前回確定値と現在表示値の両方との差が位置10mm以下かつ回転0.5°以下なら、表示を確定値へ35%寄せる。いずれかの差が閾値を超えた場合、初回、追跡リセット後は位置・回転を即反映する。未検出の間は補正残差を含め表示を固定し、独立した補間ループは持たない。閾値と係数は実機調整前の初期値。

JSON schema 20の`experiment`は`anchorSmoothing:false`と`displayStabilization`ポリシーを区別する。採用したframeだけ`displayStabilization`に判定、差、残差、補正前後の行列を記録し、非採用frameはnull。一時スモーク検証で小揺れ抑制、位置・回転の閾値超過、累積差超過、確定値非変更、clear後の即反映を確認した。実機検証と全体品質ゲートは未実施。

## 距離別の上限付き表示補正（2026-10-22、現行）

ユーザーから、提供ログの動きは遠距離5〜4mで静止した後に前進し、約2mで再び静止したという補足を得た。初回frameから0〜10秒を遠距離の候補区間、30〜40秒を近距離の候補区間として調べた。SDKとタグの距離・真値は同一ではなく、区間内の全変化をノイズとは断定しない。遠距離冒頭の隣接確定値の差は中央値9.29mm／0.546度、75パーセンタイル18.20mm／1.06度。近距離候補区間にも大きな変化があり、これを吸収する広い補正は採用しない。

補正閾値はタグ推定距離2.5m以内で10mm／0.5度を維持し、5.5m以上で20mm／1度を上限とする。間は線形補間。上限は大きな変化を取り込まないための実験設定で、距離からノイズを厳密に推定したものではない。推定距離はタグ由来の会場内カメラ位置とマーカー位置の距離で計算する。SDKカメラ位置は閾値計算に使わない。負・非有限の距離では補正を適用しない。

前回確定値・現在表示値の両方との差が今回の閾値以内の場合だけ表示を35%更新する。それ以外・初回・追跡リセット後は即反映し、確定値・SDKカメラを変更しない。未検出中は表示を固定する。JSON schema 21では距離と今回の閾値を各採用frameに追加し、ポリシーには距離の両端と近距離／遠距離の閾値を記録する。

`audience-anchor-input-s1-f292.json`の採用観測270件を新フィルターに通す軽い再処理では、補正123件（旧84件）。遠距離候補0〜10秒は29/48件（旧15/48件）、近距離候補30〜40秒は55/76件（旧55/76件）。再処理中の確定値と表示値の最大差は約12.37mm／0.631度。補正作動回数と計算上の残差の比較であり、見た目の震え削減率や精度改善の実証ではない。撮像とSDK姿勢の同期不明という制約も変わらない。

一時スモーク5件で近距離維持・線形補間・遠距離上限、無効距離、位置／回転超過の即反映、累積差超過、原値非変更、clear、原点以外のマーカーに対するSDK非依存距離と上記ログ再処理を確認。検証ファイルは保持せず、回帰テストと全体品質ゲートは軽いデバッグ指定に従い実行しない。実機での新設定の効果は未確認。
