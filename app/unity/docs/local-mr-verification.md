# サーバーなしでの複数Quest配置検証

`ArucoPresentationTest` はAPK内のDeliveryとRuntime Snapshot fixtureを読み込み、マーカー校正後にローカルのプレゼンを表示します。認証、Session、素材配信、サーバー接続は不要です。各端末が独立して同じfixtureを動かすため、ページ送り・再測定・初期化は端末間で同期しません。

表示は既存のNative UI placeholder（文字・primitive）です。Baked画像アセットの取得や本番のSurface描画、複数端末同期が成功したことを確認するシーンではありません。座標の責務は[マーカー原点とプレゼン表示の接続](aruco-presentation-origin.md)を参照してください。

## 準備

- Quest 3 / 3Sを1〜3台と、コントローラーを用意する。
- [OpenCVとPassthrough Cameraの設定](../README.md)を行う。カメラを利用するため、実機ではカメラ権限を許可する。
- ArUco `DICT_4X4_50` のID 0マーカーを、黒枠の外寸20cmで印刷する。すべての端末で同じ物理マーカーを利用する。
- Unityで `Unframe > Diagnostics > ArUco > Open Presentation Test Scene` を実行し、`Build Presentation Test APK` または `Build and Run Presentation on Quest` を実行する。

マーカー検出にはAndroidの `UNFRAME_OPENCV_FOR_UNITY` が必要です。専用builderはOpenCV本体またはdefineが不足している場合にビルドを中断します。カメラ映像が見えても検出が無効なら校正は進みません。

生成先は `Builds/PCA/unframe-aruco-presentation.apk`、アプリIDは `dev.unframe.pca.presentation` です。同じAPKを各端末へインストールします。ローカル認証設定はビルド中に除外され、ビルド後に復元されます。

## 1台で確認する

1. 起動後、カメラ権限を許可する。中央のカメラ診断と中央下のプレゼン状態表示を確認する。
2. マーカーを正面から読み取り、校正が確定するまで静止する。未校正中はプレゼンが非表示になる。
3. 校正後、両眼で表示でき、頭を動かしても表示が同じ場所に保たれることを確認する。
4. 右コントローラーのAで次のローカルeventへ進む。左コントローラーのXでfixtureを初期状態から開始する。アニメーションが進行中の場合は完了を待つ。
5. B/Yで再測定する。プレゼンが非表示になり、マーカーを測定し直すと表示が戻ることを確認する。
6. スリープからの復帰、再センタリング、追跡喪失でも、校正が解除されて再測定が必要になることを確認する。

EditorのSpace/Enter入力はfixtureの診断用です。実機の校正とコントローラー操作の代わりにはなりません。

## 2〜3台で確認する

1. マーカーを動かさず、各端末で順に同じマーカーを測定する。
2. 各端末を異なる位置から観察し、同じfixtureが同じ位置・向き・大きさで見えることを確認する。
3. 各端末で同じevent番号まで進めて比較する。操作は各端末で個別に行う。
4. 1台だけB/Yで再測定し、他端末の状態には影響せず、再測定後も位置が一致することを確認する。

マーカーを移動すると、すでに校正した端末と新しく校正した端末の基準が異なります。位置を比較するときは全端末を同じマーカー位置で再測定してください。

実機検証では端末数、使用マーカー、表示位置のずれ、追跡復帰時の挙動、両眼描画、フレームレートを記録します。このシーンの自動テストは状態遷移・参照配線・操作の受け付けを検証し、物理空間での精度やカメラ権限の動作は実機で確認します。

## 自動検証の結果

2026-10-07にOpenCV有効構成のEditModeテスト483件と、ローカルSceneのARM64 IL2CPP APKビルドが成功しました。変更したC#のフォーマット、`.meta`整合性、GUID重複、Runtime managed依存も確認済みです。

Quest 3の1台で1280×960のカメラ映像、ID 0の検出・姿勢推定・校正確定、プレゼン表示とEvent 1/35から4/35への進行を確認しました。背景パネルが文字を遮る配置を確認し、中央の背景を文字の奥へ修正しています。B/Y再測定入力はプレゼン操作側だけが処理するようにしています。複数台の位置合わせはユーザーから検証済みとの報告を受けています。端末数・誤差の測定値は記録されていません。

背景と入力所有を修正したAPKについても、同日にユーザーがQuest実機で動作を確認し、異常な挙動はなかったと報告しています。複数台の位置合わせについても、その後ユーザーから検証済みとの報告を受けています。
