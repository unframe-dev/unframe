# 腕モーションによるローカル進行

UnityのUIプレビューで、次の場面に割り当てたプリセットの動作で進行できます。片腕の動作は左右どちらのコントローラーでも成立します。Presenterで校正が完了し、プレゼン開始後にのみ受け付けます。Audience・校正中・退出確認中・アニメーション中は認識履歴を破棄します。

| プリセット   | 動作                 |
| ------------ | -------------------- |
| SwipeLeft    | 腕を左へ振る         |
| SwipeRight   | 腕を右へ振る         |
| SwipeDown    | 腕を振り下ろす       |
| SwipeUp      | 腕を振り上げる       |
| PushForward  | 正面へ押し出す       |
| PullBackward | 手前へ引く           |
| SpreadHands  | 近い両手を広げる     |
| CloseHands   | 広げた両手を近づける |

## 設定と操作

`Unframe > UI > Open Presentation UI Preview` でシーンを開きます。`Marker Presentation Controller` の `QuestLocalArmMotionControls` にある `Cues` で、進行先のローカルevent番号とプリセットを設定します。event番号2は最初の場面から次へ進む操作です。同一番号には1つだけ割り当てます。これはローカルfixtureの設定であり、本番のCue定義ではありません。

デモのevent 2〜35には表の順で8種類を繰り返し割り当てています。プレゼン中のUIに次の動作が表示されます。少し静止してから指定方向へ動かしてください。動かしたまま保持しても連続で進まず、次の認識には再び静止が必要です。アニメーション中は待機表示になります。既存のNext/A、Xによる初期化も利用できます。ボタン・トリガーの操作中は腕の認識を停止し、UI操作による誤進行を抑制します。

## 判定の既定値

- 静止0.20秒で認識準備。
- 片腕は0.28m以上、1.20秒以内、平均速度0.25m/s以上。指定方向からの横ずれは主方向の変位の65%以下。
- 広げる操作は両手間0.50m以下から0.60m以上へ、縮める操作は0.60m以上から0.50m以下へ。
- 両手間の距離変化0.30m以上、左右それぞれも初期中心から0.10m以上離れる／近づくことが必要。片手だけを動かしても成立しません。
- 水平方向は動作開始時の頭の向き、上下は重力方向を基準とします。頭と手の共通の平行移動を除外し、頭の向きだけを変えても進みません。
- 必要な追跡が失われる、無効な座標・時刻が入る、フレームが0.50秒を超えて欠ける場合は再準備します。

判定閾値は実機での調整前の既定値です。通常動作で誤進行しないこと、腕の可動範囲、左右手と両手の検知率をQuest実機で確認する必要があります。コントローラーの位置を使い、肘や肩の骨格は判定しません。

## 通信との境界

`ArmMotionRecognizer` は入力取得・UI・進行処理を持たない判定器です。`QuestLocalArmMotionControls` が既存のQuest Trackingから位置を取得し、既存のローカル進行権限に従って接続します。

既存の通信側Motionは単一対象の移動距離と時間窓のみで、方向・両手距離の条件を表現できません。本番導入には、共有Trigger契約、Realtimeの判定、Authorの場面別選択UIへの追加が必要です。Unityから検知結果を汎用next入力として送ってサーバーのMotion判定を迂回する接続は追加していません。既存のTracking/Control wireとネットワーク入口は変更していません。
