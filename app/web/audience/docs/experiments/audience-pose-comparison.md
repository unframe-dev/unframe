# 同一画像でのタグ位置とSDK移動予測の比較

> 履歴（2026-10-22）：現在の実装は[AprilTag採用方式](./audience-apriltag-adopted.md)のみ。以下は当時の方式・スキーマ・実証の記録であり、削除済みの比較モードやコマンドを現行仕様として使用しない。

2026-10-21。位置のずれを調べる試験を、静止・回転・横移動の1回へまとめる。旧anchorの融合・平滑化・外れ値保留・独自尺度較正は実行コードから撤去した。

## 先行実証

SDK単独absoluteの2本はNORMALへ到達した。続くstaged実機ログには2セッションあり、NORMAL後の2Hz検出ONを約19.26秒／21.57秒観測した。両方ともON中の全pipeline更新がNORMALで、OFF後も約12.3秒／9.8秒はNORMALだった。SDK報告768×1024を縮小せず使用し、実効検出頻度は約1.87／1.90Hz。NORMAL到達は約14.13秒／8.29秒。検出開始順序は成立したが、先行方式の初期化不成立の原因確定や空間精度の実証ではない。

## 今回固定する条件

- URLは `/?mode=anchor&detector=april&size=22.5`。既定と同じ。
- SDK尺度はabsoluteのみ。SDKが連続5秒NORMALになってから、Worker生成と上限なしの画像取得・検出を自動開始する。開始前はreadbackしない。
- 黒い外周15cm、白い余白込み22.5cmの単一ID 0。大きいサイズは既存プロファイルで選べる。
- 画像はSDK報告のvideo全体、縮小なし。選択した検出器だけを初期化・実行する。旧2Hz・両検出器の負荷条件とは異なる。
- タグ位置推定はtagモードと同じ受入基準（重複ID・曖昧姿勢・再投影誤差超過を除外）。SDK予測との差による外れ値保留、平滑化、独自の尺度推定は行わない。

## 一度の操作

1. 模様のある明るい場所で開始し、SDK初期化と自動検出開始を待つ。タグ全体を映し続ける。
2. 「静止」で約5秒保持する。
3. 「回転」へ進み、タグを画角に残して端末の向きを左右へゆっくり変える。
4. 「横移動」へ進み、向きをなるべく保って約50cm横に動かして戻る。50cmは操作の目安であり、アプリが実測した真値ではない。
5. JSONを保存する。停止後にも保存できる。

今回はタグ不可視・遠距離・長時間保持・検出負荷のON/OFF・尺度設定比較を行わない。SDK NORMALは空間精度の保証として扱わない。

## 比較の定義

Tは会場座標から見たタグ推定のカメラ姿勢、SはSDK座標から見たカメラ姿勢とする。前回の有効な観測をp、今回の同一画像取得callbackに付属する姿勢をcとする。

```text
SDK相対移動     = inverse(S_p) * S_c
今回のSDK予測   = T_p * inverse(S_p) * S_c
タグ相対移動    = inverse(T_p) * T_c
比較差         = 今回のSDK予測 と T_c の位置距離・回転角差
描画用予測姿勢 = inverse(今回のSDK予測) * venueFromMarker
```

比較は今回のタグを反映する前に行う。その後、今回のタグ・SDKペアを次回の参照へ無条件に採用する。初回は参照の設定だけで差はnullとし、0として数えない。同じ画像の再利用・時刻逆転は比較しない。タグ位置が得られない場合、SDK姿勢不成立、追跡LIMITED、hidden、停止、再開始で参照を消す。参照間隔が1.5秒超またはセッション変更なら、新しい基準から再開する。

これにより短い観測間隔での接続誤差を測る。毎回参照を更新するため、小さい誤差の長時間累積・不可視中の保持性能を検証したことにはならない。

## 表示とログ

緑はタグ直接推定、ピンクは前回タグ＋SDK移動の予測。両方を検出に使った同じ画像へ投影する。ライブ映像へ過去の検出結果を重ねない。画像の経過時間を示し、描画遅延を位置ずれと混同しない。

JSONはschemaVersion 16 / mode `anchor-comparison`。姿勢比較・差の単位はメートルとラジアン。UIではcmと度へ換算する。区間ラベル、前回frame ID、比較間隔、両姿勢、相対移動、タグ受入理由、SDK状態、画像と画面の寸法、Kと投影行列、取得／処理時刻、両検出器の時間、adapter通算計測、リング欠落件数を記録する。画像画素はJSONへ含めない。カメラ停止・再開はsessionIdで区別する。

タグとSDKは同じcallbackに対応づけるが、SDK公開インターフェース上でセンサー露光時刻と姿勢時刻の同期は確認できていない。検出完了時点の最新SDK姿勢を代用しない。

## 解釈

静止中の揺れ、回転中の差、平行移動中の差を同じログで比較する。回転時だけ差が大きい場合は時刻対応・回転変換・画角依存を、平行移動で差が増える場合は尺度・移動推定を優先して調べる。ただし差だけでSDKかタグのどちらが真値に近いかは確定できない。K・画面寸法・処理時間との相関も同時に見る。

## 検証範囲

ユーザー指定に従い、回帰テストは追加・実行しない。一時スクリプトで任意の会場回転／平行移動、カメラ回転＋横移動の一致、10cmの移動差を今回参照の更新前に測れること、予測投影の逆変換、重複画像、SDK欠落、セッションと長い観測間隔の境界を軽く確認した。実機のずれ改善は次のログで確認する。全体品質ゲートは実行せず、Audienceの型検査・lint・本番ビルドを確認する。

型検査・lint・本番ビルドは成功。一時UIデバッグで自動開始・区間切替・schema14保存（当時）・停止後のログ保持を確認した。準備中にLIMITED→NORMALへ戻っても連続5秒を待ち直すことも確認。独立レビューの指摘を修正済み。公開HTTPSのentry JavaScriptとローカル最終ビルドの一致を確認した。実カメラでの精度確認・回帰テスト・全体品質ゲートは未実施。

## 姿勢探索の更新

schema14ログの再計算で、POSIT由来の2初期値がより低誤差の姿勢を見逃す例を確認。画像由来の反転初期値を追加し、候補の診断を保存するschema15へ更新した。SDKをタグ推定へ使用せず、操作・比較の定義は同じ。[調査記録](./audience-pose-solver-investigation.md)を参照。

## 処理頻度の更新

固定2Hzを撤廃し、選択検出器・画像転送・最大速度のschema16へ更新。[高速化の条件](./audience-detection-throughput.md)を参照。
